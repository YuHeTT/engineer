### 🔴 M1 详情：地形 glb 是怎么没的

我核对了三处，可以确定：

| 检查 | 结果 |
|---|---|
| 文件系统 `Assets/可能用到的建模/土地/` | **只有 8 个 png，没有 glb** |
| 文件系统 `土地plus/` | **只有 4 个 png，没有 glb** |
| **Git 索引**（1442 个跟踪文件） | **`土地/` 下只有 png + 1 个 mat，`.glb` 从未被提交过** |

**结论**：那 4 个地形 glb（`平川台.glb` / `泽洼域.glb` / `崇岭阶.glb` / `高原坪.glb`）
和 `土地plus` 的 4 个 glb **从来没进过 Git**，所以只要本地文件被删就彻底丢了。

它们大概是在你说"一些 blend 文件……直接删除"那次被一起清掉的
（当时我删的是 `.blend`，glb 应该是你在同一批操作里删掉的）。

**好消息：`.blend` 源文件都在**，可以重新导出：

```
BlenderSources/土地/平川台.blend       ← 可导出 平川台.glb
BlenderSources/土地/泽洼域.blend
BlenderSources/土地/崇岭阶.blend
BlenderSources/土地/高原坪.blend
BlenderSources/土地plus/01_干燥起伏土壤.blend  ← 这 4 个是风格变体，不是地形类型
BlenderSources/土地plus/02_积水草地.blend
BlenderSources/土地plus/03_阶梯式黄土地形.blend
BlenderSources/土地plus/04_红色断崖平台.blend
```

**导出方式**（对齐玉米模型的做法）：用 Blender 打开 `.blend` → 导出 `.glb` →
放到 `Assets/可能用到的建模/土地/` 下，**文件名保持与之前一致**。

> ⚠️ 注意：`土地plus` 的 4 个（干燥起伏土壤 / 积水草地 / 阶梯式黄土地形 / 红色断崖平台）
> **不是"四种地形"，而是同一批地形的风格变体**（看名字就知道）。
> 策划文档要的四种地形是 `平川台 / 泽洼域 / 崇岭阶 / 高原坪`。
> **这两组是重复的两个版本，需要策划确认用哪一组。**

**如果暂时拿不到地形 glb**：可以直接用已有的 `玉米田土壤_四垄.glb`（4 m × 3 m）
平铺出一片田，先把可视化跑通 —— **不阻塞开发**。

## 三、怎么搭建（架构与做法）

### 3.1 核心原则：**数据和表现分离**

```
            Engineer.Core（不动）
                   │
        GameSession / StageMap（已有）
                   │  只读
        ┌──────────▼──────────┐
        │  FarmStageVisualBinder │  ← 唯一的桥：把数据变化转成视觉变化
        └──────────┬──────────┘
                   │ 事件/轮询
      ┌────────────┼────────────┬─────────────┐
      ▼            ▼            ▼             ▼
 CornFieldVisual RobotController GridCoverage  FarmCameraRig
 （换玉米模型）   （移动+探测）   （覆盖率）      （相机）
```

**关键约定**：可视化层**只管显示**，不参与任何数值计算。
玉米该显示"好"还是"差"，问 `GameSession.Growth`；覆盖率是多少，由 `GridCoverage` 自己数格子。

### 3.2 场景结构（建议）

```
FarmScene.unity（新场景，或复用 UI.unity 加一块）
├── Environment
│   ├── Sun (Directional Light)
│   ├── SkyBox
│   └── FieldGround           ← 地形 / 土壤块
├── CornField
│   ├── GridAnchor            ← 网格原点，规划田块范围
│   └── Plants/               ← 运行时生成的植株实例（对象池 / 实例化）
├── Equipment
│   ├── RV                    ← 房车（含开合 Animator）
│   └── Robot                 ← 机器人（⚠️ 缺模型，先用胶囊体占位）
├── Cameras
│   ├── Camera_Overhead       ← 俯视（默认）
│   └── Camera_ThirdPerson    ← 第三人称跟随
└── UI_Root                   ← 复用现有 Canvas（HUD 叠在 3D 之上）
```

**Camera 两档切换**是这个场景最省事又最出效果的设计：
文档要求"第三人称"，但概念图是俯视 —— 两档都做，默认俯视，按键切换，两种理解都满足。

### 3.3 需要写的脚本（6 个）

| 脚本 | 职责 | 依赖素材 |
|---|---|---|
| `FarmStageVisualBinder` | 监听 `GameSession` 的阶段/长势，通知各视觉组件刷新 | 无 |
| `CornFieldVisual` | 按网格生成植株；按 `GrowthLevel` 换模型；必要时缩放 | 玉米 9 个 glb |
| `GridCoverageTracker` | 维护 N×M 网格的"已探测"标记，算覆盖率，按顺序揭示数据 | 无 |
| `RobotController` | 手动（WASD）/ 自动（S 形路点）；挂球形触发器 | 机器人模型（可占位） |
| `FarmCameraRig` | 俯视 / 第三人称切换与跟随 | 无 |
| `RvAnimator` | 触发房车的开合动画 | 房车 fbx |

**建议做法：写一个编辑器构建脚本来自动搭场景**（类似现有的 `UiWhiteboxBuilder`）。
理由：田块网格要摆几百株玉米，手工拖不现实；脚本化之后能一键重建、能进版本管理。

### 3.4 玉米与阶段的对应关系（**必须策划确认**）

UI 有 5 个阶段，但玉米只有 **3 个阶段模型**。文档说"S1 只见土地、S5 与 S4 共用贴图"，所以：

| UI 阶段 | 建议用哪个模型 | 依据 |
|---|---|---|
| S1 播种苗期 | **不显示植株** | 文档："第一阶段只看的到土地" |
| S2 营养旺长期 | `幼苗`（0.28~0.42 m） | 阶段名对应苗期 |
| S3 生殖关键期 | `成长`（1.00~1.51 m，无果穗） | 阶段名对应营养生长 |
| S4 灌浆成熟期 | `成熟`（1.50~2.26 m，带果穗） | 阶段名对应灌浆成熟 |
| S5 收获期 | 与 S4 共用 | 文档明确 |

**这个映射是我按阶段名推断的，需要策划点头。** 一旦定了，改配置就行。

### 3.5 田块规模 ⚠️ 有一个需要先定的问题

土壤块是 **4 m × 3 m**，而玩家输入的土地面积默认 **10 亩（约 6667 m²）**。

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 有限演示田块**（推荐） | 只铺一块几十平米的田（比如 8×5 个土壤块 ≈ 32 m × 15 m） | 视觉上饱满、真实；**不需要缩放模型** | 与实际"10 亩"不一致 |
| B. 按实际面积铺 | 铺满 6667 m²（要 550+ 个土壤块） | 与面积一致 | 玉米会有上千株，性能与美术成本都高 |
| C. 缩放到"看着差不多" | 把土壤块放大，玉米按比例缩 | 省事 | 玉米株高就不对了（成熟 1.95 m 会变成 0.2 m） |

**推荐方案 A**，并在界面上把这个田块标注为"示范田块"（而非全部 10 亩）。
概念图里的人视角也让田块看起来是有限的一块，所以 A 更符合原始设计。

**这个要策划确认**。

## 四、现有素材是否足够？

**结论：能做出"能看懂"的农场，但离"好看"还差 3 样东西。**

| 需求 | 现状 |
|---|---|
| 玉米植株 | ✅ **充足**（9 个模型，3 阶段 × 3 长势，比例标注清楚） |
| 土壤 | ✅ 够用（4×3 m 土壤块，可平铺） |
| 房车 | ✅ 有（含开合动画） |
| **地形** | ⚠️ **glb 需重新导出**（`.blend` 源文件在），或用土壤块平铺替代 |
| **机器人本体** | ❌ **没有**。文案说"无人机 + 地面巡检机器人"，但从未建过模型 |
| 天空 / 环境 | ❌ 没有，需要一张天空盒贴图或用 Unity 内置 |
| 周边静态物 | ❌ 没有 |
| 音效 | ❌ 没有 |

### 还需要补的素材（给美术的清单）

**必须**：

1. 🔴 **地形 glb**（4 个）—— 从 `BlenderSources/土地/*.blend` 导出，或确认改用 `土地plus`
2. 🟠 **机器人模型 1 个** —— 履带式或轮式巡检机器人，带一根可伸缩的探测杆更好。
   **最低成本替代**：用胶囊体 + 一个球形探测范围，也能演示
3. 🟠 **天空盒贴图 1 张** —— 或直接用 Unity 的 Procedural Skybox（零成本，效果够用）

**建议**（有则更好）：

4. 🟡 田埂 / 围栏 / 简易道路（各 1~2 个）
5. 🟡 远景树线（可以用一张带透明通道的 billboard 贴图代替建模）
6. 🟡 其余 3 套地形的材质

**可以不做**：

- 近景特写用的叶片叶脉细节（`说明.md` 里提到当前叶片是"工程演示级简化"，
  但演示时玩家不会凑近看，**低多边形完全够用**）
- 无人机（简介里提了但没设计，建议**从文案里删掉**，或补设定）

## 七、一句话总结

**素材"半够"**：玉米（9 个模型，规格标注很详细）和房车都有，**足够开始搭**；
但 **4 个地形 glb 丢失了**（`.blend` 源文件还在，可重新导出），
**机器人模型从来就没有过**。

**搭建思路是"数据/表现分离"**：新增 6 个可视化脚本，
用一个 `FarmStageVisualBinder` 把 `GameSession` 的长势/阶段变化翻译成视觉变化，
其余脚本各自负责玉米、网格覆盖、机器人、相机。

**建议先定 6 个问题里的 Q1~Q4**（尤其 Q3 玉米映射、Q4 田块规模），
然后按第五节顺序推进 —— **第 1~5 步约 3.5 天就能出可录制的演示画面**。

# 巡航采集与分析闭环优化（2026-10-16）

> 最新交互：巡航完成 → 更新数据（留在巡航页）→ 返回农场 → 开始分析。允许同阶段重新巡航采集；旧文中“更新后直接分析”已由本节流程替代。

本轮按用户反馈修复“可以跳过巡航、采集值不更新、分析来源不明确”。未提交/推送 Git。此处是巡航观察数据与推荐的改造，不改挂起项 D1 的真实土壤演变规则，不引入新的水分胁迫公式。

## 现在的操作流程

1. 农场 S1–S4 显示本阶段采集进度。未探测项显示“待巡航采集”，已探测项显示数值与“探测”标记。
2. 点击主按钮进入巡航页，选择手动或自动巡航。未覆盖区域仍保留原蓝色遮罩；覆盖区域正常显示。
3. **必须真实覆盖 100%**，才可点击“更新数据”。原 80% 阈值不再允许分析；覆盖完成也不会未经确认就自动提交分析。
4. 点击“更新数据”确认本阶段探测快照后，直接进入分析页。适宜度、推荐肥料、推荐用量、推荐灌溉均以这份已确认观测值为输入。分析页标出来源，并列出 pH/OM 与 N/P/K 的观测数值。
5. 玩家提交水肥后，真实土壤按既有 SoilAdvance 演变，阶段推进，巡航覆盖和确认状态立即清零。下一阶段重新采集。
6. 收获期无需再巡航，继续按原流程查看收益。

## 两类数据各自用于什么

| 数据 | 用途 |
|---|---|
| 机器人确认的观测快照 | 农场/巡航界面探测数据显示；分析页五项适宜度；水肥推荐与预填值 |
| 内核真实土壤及实际投入 | 水肥演变、阶段真实肥力、长势和最终产量；不被观测误差直接覆盖 |

因此测量误差可以通过推荐影响玩家决策，但不会因为“读了一次传感器”就改写土壤。静态四项仍仅展示，不进入产量系数。收益表仍展示真实模拟结果，与分析页的观测结果可能有差异，这是两个数据来源，不再将它们混称为同一份值。

## 修复点

- 状态机 GoTo(Analyze) 统一检查确认状态；未满足时转入巡航页，不能靠旧白盒按钮跳过。后端 CommitStageDosage 也检查，避免只限制界面按钮。
- 常驻 GameFlowController 同步网格覆盖；巡航页切到农场后采集仍继续。FarmStageScreen 每 0.15 秒刷新进度/数据，巡航页仅在覆盖变化或重新进入时刷新探测列，避免每帧重复格式化所有文本。
- FarmProbeState 改为纯 C# 阶段快照，绑定 Session、阶段和真实土壤对象身份。反复打开页面不重新随机、不丢进度；新局、新阶段、重新扫描都会使旧确认失效。
- 覆盖增加时使用固定误差方向，并沿用既有 10%→5% 幅度收敛。100%确认后快照冻结；不因为刷新界面随机跳值。原误差生成实际为有界伪随机，本轮没有把它改成高斯模型。
- 分析使用独立 PlanTable 与 SuitabilityResult 计算观测结果，不污染真实内核的推荐缓存或土壤。
- 真实扫描改为“上一采样点到当前点”的线段距离判定，低帧率/高速移动不会只扫描终点而漏掉中间区域。覆盖度仍采用既有格子中心与面积权重定义，并非高精度连续土壤测绘。
- 自动巡航走完主路线后，追加未覆盖格子中心的补扫路点，实际到达/经过后才增加覆盖；不把路点进度误当成覆盖率。
- G/FinishNow 现在只提前停止并保留实际覆盖率，不再 MarkAllScanned；缺少巡航组件时不再用一键完成兜底伪造数据。
- 自动巡航结束后按现有 returnAfterAutoCruise 选项返回确认页；未扫完不能确认，仍可重扫。
- 提交、重新开始、重新初始化即时清理探测与网格状态；返回历史中的分析页也受本阶段确认约束；返回时补回键盘输入策略。

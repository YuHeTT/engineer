## 1. 构建与验收步骤

1. 打开 Unity（工程根目录即本仓库），等编译完成、Console 无红字。
2. 菜单 **Tools ▸ UI ▸ 构建白盒界面（12 屏）**。
   * 首次运行会先导入 **TMP Essential Resources**（中文字体材质的着色器依赖它），弹窗提示「再点一次」。
   * 导入完成（Console 出现导入日志、编译结束）后，**再点一次同一菜单**，即完成构建。
3. 打开 `Assets/Scenes/UI.unity`，Console 会打印「已构建 10 个屏」。
4. 直接按 **Play**，从初始界面一路点到收益计算，走通第 5 节的流程。

命令行（无人值守、不弹 TMP 提示时使用；Unity 关闭状态下才可）：

```powershell
& "D:\apps\unity\visual_studio\2022.3.62f2c1\Editor\Unity.exe" -batchmode -quit `
    -projectPath "d:\apps\unity\unity projects\engineer" `
    -executeMethod Engineer.UI.EditorTools.UiWhiteboxBuilder.BuildFromCommandLine `
    -logFile ui-build.log
```

离线语法自检（不启动 Unity，用 Unity 自带 Roslyn 编译全部脚本）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Temp\compile_whitebox.ps1
```

## 2. 场景结构总览

```
UI.unity
├─ Main Camera                     （构建器自动补齐，深色纯色底）
├─ EventSystem + StandaloneInputModule（构建器自动补齐，uGUI 必需）
└─ UI_Root                         （整棵界面树的根，重建时整体删除再生成）
   ├─ Screen_Canvas                Canvas(ScreenSpaceOverlay) + CanvasScaler(1920×1080, Match 0.5) + GraphicRaycaster
   │  └─ Screens
   │     ├─ Screen_Welcome        … Screen_Revenue   （10 个屏，见第 3 节）
   └─ UI_Flow                       GameFlowController（持有全部屏，负责互斥显示与点击路由）
```

* 布局全部用**分数锚点 + offset**（`UiLayout.Stretch / SplitLeft / SplitRight / TopBand / BottomBand / GridCell / Center / Place`），任意分辨率不散架。
* 所有屏常驻场景，只切 `SetActive`，不销毁重建；「上一步返回」走状态机历史栈。
* HUD 类屏（农场 / 机器人）的层级是 `ViewPlaceholder`（3D 画面占位）+ `HUD`（贴边信息）+ `BottomBar`（底部按钮条）。
* 概念类屏（初始 / 简介 / 选择 / 输入 / 确认 / 分析 / 收益）的层级是 `Header`（标题+副标题+分隔线）+ `Body`（主体）+ `Footer`（左下返回 + 右下主按钮），弹窗屏额外带 `Backdrop` 压暗层。

## 5. 交互流程（点着走一遍）

```
初始界面 ──「项目简介」──▶ 项目简介 ──「知道了」──▶ 初始界面
   │
   └─「开始体验」──▶ 土地类型选择（只能选平川台）──▶ 土地基础数据设置 ──「下一步：选择植物类型」──▶
        植物类型选择（只能选玉米）──▶ 确认选择 ──「进入农场」──▶ 农场主界面（S1）
                                                                       │
                                  ┌────────────────────────────────────┤
                                  │                                    │
                        「机器人检测」                          「开始分析」（S1–S4）
                                  ▼                                    │
                        机器人操控（手动/自动巡航 → 更新数据）            │
                                  │                                    │
                                  └────「更新数据」回农场（数据已写入）────┘
                                                                       │
       ┌───────────── 阶段循环（S1→S2→S3→S4→S5）────────────────────────┘
       │  开始分析：左侧建议 + 右侧填 5 项水肥量 →「确认本阶段方案」→ 写回数据 + 阶段 +1 → 回农场
       ▼
   农场主界面（S5 收获期，主按钮自动变「收益计算」）──▶ 收益计算 ──「开始新的模拟」──▶ 初始界面（数据全部复位）
```

* 每一屏左下角都有 **「上一步返回」**，走 `GameFlowController.Back()` 的历史栈回退（不是硬编码目标）。
* 所有跳转都写进 `PlaceholderScreen.actions`（构建器填），运行时由 `GameFlowController.SetFlow()` 统一 `AddListener`，**不需要在 Inspector 里手动拖引用**。

## 6. 数据流（`GameContext`）

| 数据 | 写入时机 | 读取时机 |
| --- | --- | --- |
| 土地 / 植物类型 | `GameContext` 默认值（平川台 / 玉米） | 确认页配置一览 |
| 土地面积 `LandAreaMu` | 默认 10 亩（第 7 节缺口 ①） | 机器人屏「未覆盖面积」换算 |
| 5 项动态指标 `Ph / OrganicMatter / AvailableNitrogen / LabilePhosphorus / Potassium` | 「更新数据」时由 `RobotCruiseScreen` 用探测值覆盖 | 农场屏「所有数据」、机器人屏「原数据」 |
| 4 项静态指标 `StaticIndicators` | 默认 470 / 11 / 9 / 0.07（后续在第一阶段随机生成） | 农场屏「所有数据」灰显项、收益页四个不变参数 |
| 阶段 `StageIndex`(1~5) | 「确认本阶段方案」时 +1 | 农场屏阶段标题与按钮文字、分析屏阶段标题 |
| 本阶段水肥量 `StageDosage[5]` | 分析屏 5 个输入框（确认时写回） | 收益页公式与阶段表（待接入） |

## 8. 自检与已知注意事项

1. **TMP 基础资源**：`Assets/TextMesh Pro/Resources/TMP Settings.asset` 不存在时中文会显示成粉色方块；菜单构建会自动导入并提示「再点一次」。
2. **中文字体**：统一取 `Assets/fonts/msyh SDF.asset`（`UiFactory.Font`），缺字体时回退 TMP 默认字体并打警告。
3. **构建幂等**：每次构建先删掉 `UI_Root` 再整棵重建，可以反复执行；手动在场景里改 UI 会被下一次构建覆盖（要保留的改动请改构建脚本；**素材皮肤例外**——手工挑的图用「皮肤：记录当前皮肤到映射文件」存进 JSON 后会被自动套回，见第 9 节）。
4. **离线语法自检**：`Temp/compile_whitebox.ps1` 用 Unity 自带的 Roslyn（`Editor\Data\DotNetSdkRoslyn\csc.dll` + `NetCoreRuntime\dotnet.exe`）编译 `Assets/Scripts/UI/**`（运行时 + Editor 两遍），可在不打开 Unity 的情况下确认脚本无编译错误。
5. **文案集中管理**：所有字符串都在 `UiWhiteboxContent.cs`（`UiContent`），改文案不用动布局代码。
6. **布局常量**：尺寸、间距、配色都在 `UiWhiteboxTheme.cs`（`UiTheme`）与 `UiWhiteboxLayout.cs`（`UiLayout`）。
7. **素材皮肤**：见第 9 节；白盒默认不引用任何素材，摘掉皮肤不影响逻辑。

## 9. 换素材（皮肤）

白盒默认是纯色块。要填 EPS 素材，用 `Assets/Scripts/UI/Editor/UiSkin.cs` 这套工具
（挑图与九宫格细节见 `Docs/EPS素材-清单与使用说明.md` 第 3、4 节）：

| 菜单 | 作用 |
| --- | --- |
| Tools ▸ UI ▸ 皮肤：套用 EPS 素材（当前场景） | 按元素**角色**（`UiSkinSlot`）铺素材 + 套映射；默认配了 `Panel` / `Button` / `ButtonPrimary` 三个角色 |
| Tools ▸ UI ▸ 皮肤：记录当前皮肤到映射文件 | 把手动挑的图存进 `Assets/UIresources/白盒皮肤映射.json`，重建界面后自动套回 |
| Tools ▸ UI ▸ 皮肤：构建时自动套用（开关） | 打开后「构建白盒界面（12 屏）」会顺手把素材铺上 |
| Tools ▸ UI ▸ 皮肤：文字配色同步为青蓝（开关） | 暖橙文字色 ↔ 青蓝（配套青蓝素材）；按钮 `ColorTint` 一并中性化 |
| Tools ▸ UI ▸ 皮肤：清除皮肤 | 删映射 + 关开关 + 重建 = 回到纯色白盒 |
| Tools ▸ UI ▸ 皮肤：打开映射文件 | 用系统默认程序打开 JSON，可手改 / diff / 删条目 |

元素 ↔ 角色：面板 `Panel`、HUD 数据面板 `PanelSoft`、选项卡片 `Card`、全屏底图 `ScreenBackdrop`、
压暗层 `ScreenDim`、按钮 `Button` / `ButtonPrimary`、进度条 `BarTrack` / `BarFill`、
分隔线 `Divider`、输入框 `InputField`、圆仪表 `Gauge`。

* 角色在**构建时**由 `UiWhiteboxFactory` 自动登记（`MakeImage / MakePanel / MakeButton / MakeProgressBar / MakeInputField`），
  调用点要特殊角色就传一个 `UiSkinRole` 参数（如全屏底图 `ScreenBackdrop`、选项卡 `Card`）。
* 换默认素材：改 `UiSkin.Table` 里那一行路径；角色没配素材时会保持纯色并在 Console 提示，不会报错。
* 皮肤套的是 `Image.sprite`，**不动布局、不动逻辑**；按钮悬停/按下的颜色反馈仍在，只是被中性化以免染到素材。

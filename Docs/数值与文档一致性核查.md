### 2.5 最终公式

代码链路：

```text
Simulation.Commit()
  → fit.StageFertility() = fPH × fOM × fN × fP × fK
  → _stageFertility[stage]
Simulation.Revenue()
  → RevenueReport.Create()
  → YieldModel.Compute()
  → Ffert = average(已结算阶段)
  → Fwater = 1
  → Sstatic = 1
  → Y = YmaxGeo × Ffert × Fwater × Sstatic
```

- `YmaxGeo = 733`（平川台 + 玉米）✅
- `Ffert,stage` 五因子连乘 ✅
- 全四阶段 `Ffert` 取 4 阶段平均 ✅
- `Fwater = 1`、`Sstatic = 1` ✅
- 总面积产量 = 单亩产量 × 亩数 ✅（文档只定义单亩 Y，总面积是界面扩展）

固定算例：中点土壤、照抄推荐，`Ffert = 0.9375`，`Y = 733 × 0.9375 = 687.19 kg/亩`，与旧记录一致。

## 四、地形/作物 2、3、4：目前不是“数值不同”

### 4.1 地形

`TerrainDef` 只有：

```text
Id / DisplayName / Description / PlayableInV1 / ModelAssetName
```

**没有**以下数值：

- 初始动态指标上下限
- 静态指标范围
- 保水/排水系数
- 超灌惩罚权重
- `YmaxGeo`

`SimConfig.DynamicInputRanges` 和 `StaticRanges` 是**全局一份**，四块地共用平川台的范围。`GameContext.LandTypeId` 只用于 UI 文案和记录，数值内核 `Simulation` 不读它。

### 4.2 作物

`CropDef` 有 `Curves` / `Yield` 字段，但 `SimConfig.CreateDefault()` 里四种作物都是：

```csharp
Curves = c.Curves,
Yield  = c.Yield,
```

即四种作物共用玉米的 5 条曲线和同一个 `YmaxGeo=733`。`Simulation.SetCrop()` 确实会切到选中的 `CropDef`，但因为数据完全相同，结果没有差异。

`StageConsumes`、`PlanRules`、`AdvanceCoef` 也都是全局一套，没有按作物分表。

### 4.3 文档给了什么

最新 `策划方案`：

- TABLE 0 / TABLE 1：只有地形/作物的**名称和介绍**，没有数值。
- TABLE 12：`Ymax,geo` 是“该地貌 + 该作物”的理论最大值，但正文只给了 **平川台 + 玉米 = 733**。
- TABLE 18：只有**平川台**的动态/静态范围。
- 没有甜菜/红薯/土豆的曲线、Ymax、阶段消耗、推荐方案表。

所以：

> **不是代码算错，而是文档没有给 2/3/4 的独立数值。当前代码只能共用平川台/玉米；要真正“不同”，必须先补数据。**

## 五、文档自身的三处不一致（已按结论实现）

| 项 | 文档写法 | 代码处理 | 影响 |
|---|---|---|---|
| `YmaxGeo` | `数值内核...md` 旧版写 1000；最新策划方案写 733 | 用 733 | 旧文档数字已过时；代码与最新一致 |
| `Fwater` | TABLE 11 写 `(α1Fw,s1+…)/4`；但 TABLE 15 结论 `Fwater=1`，α 和为 1 | v1 的 `Fw,s` 全 1，直接取 `Fwater=1`；`WaterFactor()` 用 Σα 归一化 | 当前结果一致；若将来 Fw,s 不为 1，需确认是否仍按 ÷4 |
| S1 推荐表 | `Unity界面` 11 条无兜底；`策划方案` 12 条有兜底 | 已按 12 条实现 | 旧 11 条会给出 80 kg 有机肥，新版是 20 kg |

另外，`InputLimits`（输入钳制到建议量×5）是工程保护，文档没有定义；它可能改变“玩家输入超量”的结果，但不影响照抄推荐方案时的标准算例。

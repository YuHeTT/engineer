# 车身朝向：改成"运行时可调 + 精确诊断"

> 日期：2026-10-15
> 你反馈：改成 90° 后方向**仍然不对**，手动和自动都不对。

---

## 一、我先纠正自己的一个推断错误

上一轮我说"车身长边是侧向的，所以需要 90°" —— **这个推断没有依据**。
我这次去读了 FBX 头部的坐标轴声明：

```
FrontAxis      = 2 (Z),  sign = +1
UpAxis         = 1 (Y),  sign = +1
CoordAxis      = 0 (X),  sign = +1
```

**FBX 明确声明车头朝 +Z。** 而 Unity 的 `Vector3.forward` 也是 +Z ——
**所以理论上就不该需要 90° 偏移，0 才是对的。**

那我上一轮改 90° 是**基于错误推断的瞎猜**，改错了方向。

---

## 二、同时发现一个真实的代码漏洞

`ResetToStart()` 里设朝向时**漏了 `roverYawOffset`**：

```csharp
roverYaw = 0f;
rover.transform.rotation = Quaternion.Euler(0f, roverYaw, 0f);   // ★ 少了 + roverYawOffset
```

后果：每次重置（点巡航按钮时都会调）之后，车头会先歪一下，
即使偏移量设对了，也会看到"朝向不对"的瞬间。**已修**。

---

## 三、不再猜了：加"运行时可调 + 精确诊断"

朝向取决于**模型内部的旋转**，从文件里推断容易出错。
所以我做了两件事，让你 10 秒内能调准，而且**不用改代码重新编译**：

### ① 运行时按键调整朝向

| 按键 | 作用 |
|---|---|
| **`Z`** | 车身朝向 **+90°** |
| **`X`** | 车身朝向 **−90°** |

每次按键都会打印：
```
[农场] 车身朝向修正 = 90°（按 X 反方向转 90°）
```

**转对了就把那个数字抄到 `FarmCruiseController.roverYawOffset` 即可。**

> 注意：`Z` / `X` 只在**没在巡航时**（Idle / Finished）生效，避免巡航中误触。
> 所以在农场主界面按就行 —— 这时相机会跟车吗？不会，因为没在巡航。

### ② 进入巡航时自动打印朝向诊断

点「手动巡航」或「自动巡航」时会打印：

```
[农场] 车身朝向诊断：
  roverYawOffset = 0°　roverYaw = 0°
  模型 forward = (0.00, 0.00, 1.00)　主轴 Z
  行进方向     = (0.00, 0.00, 1.00)
  两者夹角     = 0.0°　✅ 一致
```

**这一行直接告诉你对不对**：

| 输出 | 含义 |
|---|---|
| `两者夹角 = 0.0°　✅ 一致` | 朝向正确 |
| `两者夹角 = 90.0°　❌ 不一致` | 需要 ±90 |
| `两者夹角 = 180.0°　❌ 不一致` | 需要 180 |
| `模型 forward` 的主轴是 **X** | 说明模型内部确实转了 90°，那 90 或 -90 才对 |
| `模型 forward` 的主轴是 **Z** | 说明声明与实际一致，**0 才对** |

**主轴这一项是关键** —— 它直接告诉我模型内部到底转没转。

## 六、我的反思

这一轮我犯了两个错，都值得记下来：

| 错误 | 教训 |
|---|---|
| 上一轮**凭包围盒尺寸（9.2 × 7.0 × 2.8）就推断"车头朝 X"** | 包围盒尺寸推不出朝向 —— X 是 9.195、Z 是 2.790，我当时说"Z 是车长"完全说反了。**该做的是读 FBX 的 FrontAxis，或者直接打印模型 forward。** |
| 改完 90° 后**没有验证机制**就交付 | 应该同时给出"怎么看对不对"的诊断 —— 这一轮才补上 |

**这次的做法是：不再猜数值，而是给出"可现场调 + 可自证"的工具。**
以后遇到这类"朝向 / 比例 / 位置"的问题，应该一开始就这么做。

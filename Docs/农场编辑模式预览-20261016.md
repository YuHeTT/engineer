# 农场直接编辑与保存

更新：2026-10-16。本文替代同日早期的临时预览窗口方案。

## 日常操作

打开 `Assets/Scenes/Farm.unity`，等待脚本编译和一次初始化生成完成。之后直接在 Scene / Hierarchy 中选择土壤、玉米、田间道路、外围地形、房车、小车，拖动、旋转、缩放，按 **Ctrl+S** 保存场景。无需生成、刷新、清理或烘焙按钮。

旧空骨架场景在打开或脚本重新加载时自动转为可编辑布局，并将场景标记为未保存。第一次生成后按 Ctrl+S。之后再打开、编译、进入 Play 都不会重新覆盖手工布局；仍需像普通 Unity 场景一样保存未保存的修改。

运行中的修改仍遵循 Unity 的普通规则：Play 内拖动不会自动保存回编辑场景。

## 行为与边界

- 土壤、道路、地形、房车和小车以场景物体保存；运行时复用，不再叠加生成第二份。房车开合和小车巡航继续由游戏逻辑控制。
- 玉米初始布局可以直接调整。运行时模型继续根据阶段/长势切换，切换时沿用上一份玉米实例的位置、旋转、缩放；不同阶段模型本身依然有不同大小和形态。游戏中的小车会移动，开始巡航时依旧按巡航逻辑定位。
- 手工布局优先：运行时不会因玩家选择亩数而重新排列视觉田块。输入亩数仍参与数值与收益计算，视觉块数现在由保存的场景决定。
- 已保存布局下，修改生成配置不会自动重铺场景，避免覆盖手工修改；直接编辑场景对象即可。旧的预览、重建、编辑器遮罩菜单已删除。
- 合并网格与程序材质自动保存到 `Assets/Art/GeneratedFarm/FarmLayout*.asset`。不要单独删除这些资源；它们与 Farm 场景一起使用。单个模型仍复用共享网格并启用原有合批优化。
- 若打开的是 Bootstrap 场景，编辑农场时请打开 Farm 场景（也可 Additive 打开）。游戏仍可从 Bootstrap 运行。

## Engineer 菜单清理

日常保留：`Engineer → 农场 → 自动取景（相机对齐田块）`，以及 `Engineer → 验证` 下的数值批量验证、收益链路自检。

删除失效入口及实现：编辑模式预览、只重建田块与玉米、切换未覆盖遮罩（编辑器预览）。自动场景初始化继续保留，不依赖菜单。

创建农场、创建 Bootstrap 的初始化入口移至 `Tools → Engineer → 场景初始化`，仅用于重新搭建场景。日常编辑无需使用。此次清理未修改场景内容、运行时组件或生成资源。

## 二、最重要的一件事：删了不会自动变小

**Git 会永久保留文件的历史版本。** 已经推送过的文件，光是「删掉 + 提交 + 推送」
**不会让仓库变小**——旧数据仍然躺在历史提交里，队友 clone 时照样要把那 190 MB 下下来。

想真正缩小，必须**重写历史**（`git filter-repo` / `git filter-branch`）再**强制推送**。

⚠️ **重写历史的时机非常关键：**

- ✅ **队友 clone 之前**：干净利落，只有你一个人受影响
- ❌ **队友 clone 之后**：他们的本地仓库和历史对不上，必须删掉重新 clone，
  否则一推送就产生大量冲突。如果队友本地还有未推送的提交，处理起来会很麻烦

**结论：如果决定清理，尽早做。** 越往后队友越多、未推送的工作越多，代价越大。

## 三、清理清单（按性价比排序）

### 1. 把 TMP 字体改成 Dynamic —— 省约 34 MB，零风险 ⭐最划算

`Assets/fonts/msyh SDF.asset` 有 **35.73 MB**。这是 TextMeshPro 的**静态**字体图集：
中文字库静态烘焙会把几万个字形全部渲染进贴图，体积必然巨大。

**操作（必须在 Unity 里做）：**

1. Project 窗口选中 `Assets/fonts/msyh SDF.asset`
2. Inspector 里找到 **Atlas Population Mode**，从 `Static` 改成 **`Dynamic`**
3. Atlas Settings 里把 **Atlas Width / Height 改成 1024 × 1024**
4. 应用后在 TextMeshPro 组件上确认中文仍能正常显示
5. 之后图集只会按需保存实际用到的字形，文件通常降到 1–2 MB

> ⚠️ 改成 Dynamic 后，那个 `.ttf` 源字体**必须留在工程里**（动态模式运行时要从 ttf 取字形），
> 不能删。而静态模式其实可以把 ttf 移出 Assets 省 26 MB，但动态模式更灵活，优先推荐动态。
> 改完务必在 Unity 里实际跑一遍界面，确认没有缺字。

### 2. 删除 `Assets/可能用到的建模/` —— 省 46.10 MB

**已做过严谨验证**：提取该文件夹下全部 **71 个资源的 GUID**，扫描了 6 个场景、
3 个材质、7 个 `.asset`、全部预制体 —— **零引用**。

它已被 `Assets/Art/`（64 MB）取代：正式素材整理进了 Art，这份「候选库」留在原地没人用。

**删之前请确认**：里面有部分地形模型（`土地/`、`土地plus/` 的 8 个 `.glb` 和贴图）
在 `Assets/Art/` 里**没有对应副本**。如果确定不再需要这些候选地形，可以整体删除；
否则建议先移到项目根目录（`Assets` 外面，Unity 就不会导入），再决定去留。

**重新验证引用关系的命令**（PowerShell）：

```powershell
$git = (Get-ChildItem "$env:LOCALAPPDATA\GitHubDesktop\app-*\resources\app\git\cmd\git.exe" |
        Select-Object -Last 1).FullName
$root = 'D:\ugame\engineer'
$modelRoot = Join-Path $root 'Assets\可能用到的建模'

# 1) 收集该文件夹下所有资源的 GUID
$guids = @{}
Get-ChildItem -LiteralPath $modelRoot -Recurse -File -Force |
  Where-Object Extension -eq '.meta' | ForEach-Object {
    $m = [regex]::Match((Get-Content -LiteralPath $_.FullName -Raw), 'guid:\s*([0-9a-f]{32})')
    if ($m.Success) { $guids[$m.Groups[1].Value] = $_.FullName }
  }

# 2) 扫描所有可能产生引用的文件（排除该文件夹自身）
$exts = '.unity','.prefab','.mat','.controller','.asset','.playable','.anim'
$refs = Get-ChildItem -LiteralPath (Join-Path $root 'Assets') -Recurse -File -Force |
        Where-Object { $_.Extension -in $exts -and $_.FullName -notlike "$modelRoot*" }

# 3) 求交集
$found = foreach ($f in $refs) {
  $txt = Get-Content -LiteralPath $f.FullName -Raw
  foreach ($m in [regex]::Matches($txt, 'guid:\s*([0-9a-f]{32})')) {
    if ($guids.ContainsKey($m.Groups[1].Value)) { $f.FullName }
  }
}
if ($found) { "有引用，不能删："; $found | Select-Object -Unique }
else { "零引用，可以安全删除" }
```

> 注意：不要用 `Get-ChildItem -Include *.unity,*.prefab`，`-Include` 在这里会被忽略，
> 导致把 `.meta` 文件也扫进去、误报「有引用」。上面的写法用的是 `Where-Object Extension`。

## 四、执行顺序（重要）

1. **先处理内容**：在 Unity 里改字体为 Dynamic、压图片、删/移多余文件夹
2. **在 Unity 里完整跑一遍**，确认没有缺字、没有丢失引用、场景正常
3. **提交这次清理**（这一步只是让工作区干净，历史里还有旧数据）
4. **重写历史**：

   ```powershell
   # 推荐：git filter-repo（需要单独安装，pip install git-filter-repo）
   git filter-repo --path "Assets/可能用到的建模" --invert-paths

   # 备选：内置的 filter-branch（慢，且已不推荐，但不用装东西）
   git filter-branch --force --index-filter `
     "git rm -r --cached --ignore-unmatch 'Assets/可能用到的建模'" `
     --prune-empty -- --all
   ```

5. **强制推送**：`git push --force-with-lease origin main`
6. **清理本地残留**：

   ```powershell
   git reflog expire --expire=now --all
   git gc --prune=now --aggressive
   ```

7. **通知队友删掉本地仓库重新 clone**（如果他们已经开始协作了）

## 五、日常防止仓库膨胀的规则

即使在项目期间不清理，也请守住这几条，避免它涨得比预期快：

1. **不要反复提交同一批大二进制文件。** Git 保存二进制文件的**每一个版本**。
   同一个 `.glb` 改了 10 次、每次提交一次，历史里就是 10 份（每份 11 MB）。
   做法：模型定稿后再提交，中间迭代版本不要进 Git。

2. **换了新模型就删掉旧的。** 别让 `RV_v1.glb`、`RV_v2.glb`、`RV_v2_final.glb`
   全都躺在仓库里 —— 每一份都永久占空间。

3. **`Library/`、`Temp/`、`obj/`、`UserSettings/`、`*.sln`、`*.csproj` 永远不要提交。**
   已在 `.gitignore` 里配好。如果哪天发现它们出现在 GitHub Desktop 的待提交列表里，
   说明 `.gitignore` 被改动或损坏了，要立刻检查。

4. **定位问题：**
   - 如果本来是文本的 `.cs`、`.unity` 突然显示成一团乱码 —— 是二进制资源被误标成文本了
   - 如果待提交列表里冒出几百个 `Library/` 下的文件 —— 是 `.gitignore` 失效了

5. **定期量一下体积**，涨得不对劲就早点查：

   ```powershell
   $git = (Get-ChildItem "$env:LOCALAPPDATA\GitHubDesktop\app-*\resources\app\git\cmd\git.exe" |
           Select-Object -Last 1).FullName

   # 仓库体积
   & $git count-objects -vH

   # 最大的 20 个被跟踪文件
   & $git ls-files | ForEach-Object {
     $p = Join-Path 'D:\ugame\engineer' $_
     if (Test-Path -LiteralPath $p) {
       [pscustomobject]@{ MB = [math]::Round((Get-Item -LiteralPath $p -Force).Length/1MB, 2); Path = $_ }
     }
   } | Sort-Object MB -Descending | Select-Object -First 20
   ```

## 六、什么时候必须动手

出现下面任一情况，就别再等了：

- 仓库超过 **1 GB** —— GitHub 会发警告邮件
- 单个文件超过 **100 MB** —— GitHub 会直接拒绝推送
- 队友抱怨 clone 要等太久
- 单次 push 频繁失败或超时

## 二、"拉取前能看到、拉取后看不到"的准确解释

我把自己本地 `HEAD` 版和 `origin/main` 版的 `UI.unity` 都取出来对比了三屏的脚本挂载：

| 屏节点 | `HEAD`（我本地基准 = 你拉取前的状态） | `origin/main`（队友已推送） |
|---|---|---|
| **Screen_LandParams** | `PlaceholderScreen` ❌ | **`LandParamsScreen`** ✅ |
| **Screen_Revenue** | `PlaceholderScreen` ❌ | **`RevenueScreen`** ✅ |
| **Screen_Confirm** | `PlaceholderScreen` ❌ | **`ConfirmScreen`** ✅ |
| Screen_Analyze | `AnalyzeScreen` ✅ | `AnalyzeScreen` ✅ |
| Screen_FarmStage | `FarmStageScreen` ✅ | `FarmStageScreen` ✅ |
| Screen_RobotCruise | `RobotCruiseScreen` ✅ | `RobotCruiseScreen` ✅ |

**所以**：
- **"拉取前"** = 你本地 `HEAD` 版本，三屏是通用占位屏 → `LandParamsScreen.OnPlantSelectClicked()` 从不执行 → `BeginSimulation()` 从不调用 → **数值内核从未启动** → 收益算不出来
- **"拉取后"** = 队友的 `UI.unity`，三屏挂对了 → 内核能启动

**也就是说：这个 bug 是真的，队友也已经修好了。** 我昨天的诊断方向是对的，只是**动作慢了**——队友先一步修完并推送。

## 五、唯一值得保留的两点（但不要用我的 diff 合）

### 5.1 收益屏两个列名与代码语义不符

队友的 `UI.unity` 里这两列表头仍是「本阶段水肥量」「适宜度结果」，
而 `RevenueScreen` 往第 2、3 列**实际写的是**：`fertilityText`（肥力系数）、`soilText`（关键土壤指标）。
**玩家会看错列。** 建议让队友改这两处文本（1 分钟）。

### 5.2 静态指标的标签/数值位置会颠倒 ⚠️

队友的 `RevenueScreen.EnsureResolved()` 里：

```csharp
staticValueTexts[i] = FindText("Body/DataPanel/StaticList/Static_" + (i + 1));
```

而 `FindTextsIn()` 的实现是"**先取自身，再取全部子节点**"：

```csharp
var own = t.GetComponent<TMP_Text>();
if (own != null) result.Add(own);
result.AddRange(t.GetComponentsInChildren<TMP_Text>(true));
```

`Static_1` 自身没有 `TMP_Text`，所以 `FindText` 返回**第一个子节点** = `Label`。
而 `RefreshStaticList` 往里写的是：

```csharp
staticValueTexts[i].text = name + "：" + SoilIndicators.Format(indicatorIndex, value);
```

**结果**：文字会显示在 `Label` 位置，而 `Value` 位置保持原样（可能是"—"）。
即四项静态指标会显示成 **「毒砷潜势：5.0」挤在标签格、数值格空着**。

不影响功能（数值确实显示了），但**版式颠倒**。
**建议**：改成 `FindText("…/Static_" + (i+1) + "/Value")`，或让 `RefreshStaticList` 同时写 `Label` 和 `Value`。

## 三、适宜度函数：一个类搞定全部五个指标

文档里 5 个指标的适宜度函数**结构完全相同**——保底 → 线性上升 → 最优平台 → 线性下降 → 保底。所以**只写一个函数**：

```csharp
// Core/SuitabilityCurve.cs
namespace Engineer.Core
{
    /// 五段式适宜度曲线：地板 → 上升 → 平台 → 下降 → 地板
    /// 全部由数据驱动，五个指标共用这一个实现。
    [System.Serializable]
    public sealed class SuitabilityCurve
    {
        public float B0, B1, B2, B3;   // 四个边界：B0<B1<B2<B3
        public float Floor = 0.2f;     // 两端保底值
        public float Peak  = 1.0f;     // 平台值

        public float Evaluate(float x)
        {
            if (x < B0) return Floor;
            if (x < B1) return Floor + (Peak - Floor) * (x - B0) / (B1 - B0);
            if (x <= B2) return Peak;
            if (x <= B3) return Peak - (Peak - Floor) * (x - B2) / (B3 - B2);
            return Floor;
        }
    }
}
```

### 五个指标的参数（直接填进 `SimConfig`）

| 指标 | B0 | B1 | B2 | B3 | Floor | Peak |
|---|---|---|---|---|---|---|
| pH | 4.5 | 5.5 | 7.0 | 8.5 | 0.2 | 1.0 |
| OM（腐殖丰度） | 10 | 20 | 35 | 50 | 0.2 | 1.0 |
| N（速效氮） | 20 | 70 | 110 | 150 | 0.2 | 1.0 |
| P（磷活度） | 2 | 10 | 25 | 40 | 0.2 | 1.0 |
| K（钾储量） | 40 | 100 | 200 | 280 | 0.2 | 1.0 |

> **注意**：`Evaluate` 里 `x < B1` / `x <= B2` / `x <= B3` 的等号位置必须和文档表格一致。
> 文档写 `[B1, B2]` 为平台（闭区间），上升段是 `[B0, B1)`，下降段是 `(B2, B3]`，B3 以上保底。

## 四、设计表的实现方式

### 4.1 推荐方案表 → 有序规则数组

**不能做成"条件匹配"的松散表**，因为文档的表是**有优先级的分支**（S1 前两行、S3 前两行都可能同时满足）。

```csharp
public sealed class PlanRule
{
    public Stage Stage;            // S1..S4
    public int   Priority;         // 越小越先判定
    public PlanCondition Cond;     // 条件
    public string Label;           // "有机肥+少量氮磷肥"（UI 显示）
    public string Physiology;      // 玉米生理说明（UI 显示）
    public FertilizerAmounts Amounts;   // 有效成分量
    public float BaseIrrigation;        // 单亩基准灌溉 m³/亩
}

public sealed class FertilizerAmounts
{
    public float Organic;      // 有机肥 kg/亩
    public float N, P, K;      // 氮/磷/钾 有效成分 kg/亩
    public float Compound;     // 复合肥 kg/亩（折算见 6.3）
}

public sealed class PlanCondition
{
    public ThresholdCheck AnyBelow;      // 任意项 < 阈值（-1 表示不用）
    public ThresholdCheck AnyInRange;    // 任意项 ∈ [lo, hi)
    public ThresholdCheck AnyAboveEq;    // 任意项 ≥ 阈值
    public ThresholdCheck AllAboveEq;    // 全部项 ≥ 阈值
    public int CountAboveEq;             // 至少 N 项 ≥ 该阈值
    public float CountAboveEqThreshold;
    public SoilMetric[] Scope;           // 参与判定的指标子集（如 S1 只看 fOM、fN？）
}
```

> **`Scope` 这一项需要策划确认**。文档写 S1"任意项＜0.6（优先 fOM、fN）"——
> "优先"是指**只看 fOM 和 fN 两项**，还是**看全部五项但优先补 fOM/fN**？
> v1 我按**看全部五项**实现（更保守，不会漏判），这一项做成配置。

### 4.2 判定顺序（关键，按此实现否则结果会错）

```
S1:  行1(任意<0.6) → 行2(全部≥0.6 且 ≥3项≥0.8) → 行3(其余情况)
S2:  行1(fN<0.6)   → 行2(fN<0.8)              → 行3(其余情况)
S3:  行1(任意<0.6) → 行2(任意∈[0.6,0.8))      → 行3(其余情况)
S4:  行1(fK<0.6)   → 行2(fK<0.8)             → 行3(其余情况)
```

**S1 的兜底**：文档没有第三条规则。"全部 ≥0.6 但**只有 2 项** ≥0.8"落不进任何一行。
按已确认的决策 → **归入行 1**（用 80 kg 有机肥那条，偏保守/偏肥）。

```csharp
public RecommendedPlan Match(Stage s, in SuitabilityResult fit)
{

        if (r.Cond.Evaluate(fit)) return r.ToPlan();
    return Fallback(s);   // 12 条规则每个阶段都有「其余情况」，正常不会走到这里
```

### 4.3 配置载体：推荐用 CSV + 导入器，不是 ScriptableObject

**理由**：推茬表是策划高频调整的东西。直接改 SO 资产会产生**二进制 diff**（Git 里看不出改了什么），而且多人改同一个 SO 会冲突。

| 方案 | 优点 | 缺点 |
|---|---|---|
| **CSV + 导入器** ✅ | 可 diff、策划用 Excel 直接改、冲突小 | 需要一个导入脚本 |
| ScriptableObject 直接编辑 | 无需导入 | 二进制 diff、易冲突 |
| JSON 文本资产 | 可 diff、Unity 原生支持 JsonUtility | 策划手写易出错 |

**推荐做法**：策划维护 Excel，导成 6 个 CSV 放进 `Assets/Config/Source/`：

```
Assets/Config/Source/
├── metrics.csv        五个指标的曲线参数 + 静态指标范围
├── terrains.csv       四套地形（名称/介绍/初始区间/模型引用）
├── crops.csv          四种作物（名称/介绍/模型引用）
├── plan_rules.csv     ★ 12 条推荐规则（含优先级与条件）
├── stage_consume.csv  阶段消耗量
└── advance_coef.csv   演算系数
```

## 五、条件判定的精确定义

**这是最容易实现错的地方，按此实现。**

```csharp
public enum CondType { Below, AnyBelow, AnyInRange, AllAbove, AllAboveAndCount }
```

| 判定 | 定义 |
|---|---|
| `Below(m, t)` | `f[m] < t` |
| `Below(m, t)` 表示"未达" | 即"**比阈值差**" |
| `AnyBelow(t)` | 存在 i 使 `f[i] < t` |
| `AnyInRange(lo, hi)` | 存在 i 使 `lo ≤ f[i] < hi` |
| `AllAbove(t)` | 对所有 i，`f[i] ≥ t` |
| `AllAboveAndCount(t, c, tt)` | `AllAbove(t)` 且 `count(f[i] ≥ tt) ≥ c` |

### 边界值的统一约定

> **`>= 阈值` 算"达到"，`< 阈值` 算"未达到"。**

推论（照此实现）：
- `fN = 0.8` → `fN < 0.8` 为假 → **不触发 S2 行4**，落到 **行5**（少量氮肥）
- `fN = 0.6` → `fN < 0.6` 为假 → **不触发 S2 行3**，落到 **行4**
- `f = 0.7` → `AnyInRange(0.6, 0.8)` 为真（0.6≤0.7<0.8）→ **触发 S3 行7**
- `f = 0.8` → `AnyInRange(0.6, 0.8)` 为假 → 只有 `AllAbove(0.8)` 可能为真

### 长势判定

```csharp
public sealed class GrowthRule
{
    public float GoodAllAbove = 0.6f;   // 全部 > 0.6 → 好
    public float BadAllBelow  = 0.6f;   // 全部 < 0.6 → 差
}
// 实现：
//   all(f > 0.6)          → Good
//   all(f < 0.6)          → Bad
//   其余（含全部 == 0.6）  → Normal
```

> **注意**：文档原文是"所有适宜度 >0.6"和"所有适宜度 <0.6"，**都是严格不等号**。
> 所以 `f = 0.6` 既不是"好"也不是"差"→ **正常**。这与已确认的决策一致。

## 六、演算模型

### 6.1 水肥输入

```csharp
public struct FertilizerApplication
{
    public float Irrigation;   // 实际灌溉 m³/亩
    public float Organic;      // 有机肥 kg/亩
    public float N, P, K;      // 氮/磷/钾 kg/亩
}
```

### 6.2 两个比例

```csharp
float effWater  = rec.BaseIrrigation > 0f
                ? Math.Min(app.Irrigation / rec.BaseIrrigation, 1f) : 1f;
float overWater = rec.BaseIrrigation > 0f
                ? Math.Max(app.Irrigation - rec.BaseIrrigation, 0f) / rec.BaseIrrigation : 0f;
```

### 6.3 复合肥折算

已确认比例 **1:1:1**。折算放在**进入演算之前**，把它拆成 N/P/K 有效成分：

```csharp
// compound = 14  →  N += 14/3, P += 14/3, K += 14/3
public static void ResolveCompound(ref FertilizerApplication app, float compoundRatio)
{
    float each = app.Compound * compoundRatio;   // ratio = 1f/3f per element
    app.N += each; app.P += each; app.K += each;
    app.Compound = 0f;
}
```

> **配置化**：`compoundRatio` 放配置文件，若策划后面改成 15-15-15 或别的比例，只改一个数。

### 6.4 指标演算（含 pH 系数）

```csharp
public sealed class AdvanceCoef
{
    // pH
    public float pH_Target = 6.25f;   // 有机肥把 pH 推向的目标
    public float pH_OmRef  = 80f;     // 有机肥参考量
    public float pH_OmCoef = 0.1f;    // ★ 文档原值，已知偏小
    public float pH_CoefOfOm = 1.0f;  // 有机肥把 pH 拉向目标的推力方向系数
    public float pH_NRef   = 12f;     // 氮肥参考量
    public float pH_NCoef  = 0.15f;   // ★ 氮肥酸化系数，比有机肥项强 1.5 倍
    // OM
    public float OM_GainRef  = 80f;  public float OM_Gain = 7.5f;
    public float OM_Decay    = 1.5f;  public float OM_OverPenalty = 1.5f;
    // N / P / K
    public float N_GainRef = 12f;  public float N_Gain = 20f;   public float N_OverPenalty = 4f;
    public float P_GainRef = 5f;   public float P_Gain = 7.5f;  public float P_OverPenalty = 1.5f;
    public float K_GainRef = 10f;  public float K_Gain = 50f;   public float K_OverPenalty = 10f;
}
```

```csharp
public static SoilState Advance(SoilState cur, Stage s,
                                in FertilizerApplication app,
                                in RecommendedPlan rec,
                                in SimConfig cfg)
{
    var a = app;
    ResolveCompound(ref a, cfg.CompoundRatio);          // 6.3

    float ew = EffWater(a.Irrigation, rec.BaseIrrigation);
    float ow = OverWater(a.Irrigation, rec.BaseIrrigation);

    var c   = cfg.Advance;
    var con = cfg.StageConsumes[(int)s];

    var next = cur;

    // ---- pH ----
    next.pH = cur.pH
            + (c.pH_Target - cur.pH) * (a.Organic / c.pH_OmRef) * c.pH_OmCoef * ew
            - c.pH_NCoef * (a.N / c.pH_NRef) * ew;

    // ---- 腐殖丰度 ----
    next.OM = cur.OM
            + c.OM_Gain * (a.Organic / c.OM_GainRef) * ew
            - c.OM_Decay
            - c.OM_OverPenalty * ow;

    // ---- 速效氮 ----
    next.N = cur.N
           + c.N_Gain * (a.N / c.N_GainRef) * ew
           - con.N
           - c.N_OverPenalty * ow;

    // ---- 磷活度 ----
    next.P = cur.P
           + c.P_Gain * (a.P / c.P_GainRef) * ew
           - con.P
           - c.P_OverPenalty * ow;

    // ---- 钾储量 ----
    next.K = cur.K
           + c.K_Gain * (a.K / c.K_GainRef) * ew
           - con.K
           - c.K_OverPenalty * ow;

    // ---- 静态四项：不变 ----
    return next;
}
```

### ⚠️ 6.4 必须记录的一个已知问题

`pH_OmCoef = 0.1` 与 `pH_NCoef = 0.15` 的**力度配比是反的**：

| 项 | 建议量代入 | 效果 |
|---|---|---|
| 有机肥项 | `× 80/80 × 0.1` = **+0.100** | 推向 6.25（中和酸性） |
| 氮肥项 | `− 0.15 × 12/12` = **−0.150** | 拉低 pH（酸化） |

**氮肥酸化力度是有机肥中和力度的 1.5 倍** → 照抄推荐方案，pH 会**净下降**。
实测：起点 6.90，四阶段后 6.72。

**v1 按文档原值实现**（已确认），代码里留 `// TODO 数值优化` 注释。
后续修改只需把 `pH_NCoef` 从 `0.15` 调到约 `0.05`，**不改代码**。

## 八、总入口 `Simulation`

**设计要点：能单步推进**，这样 UI 才能在阶段之间插入玩家输入。

```csharp
public sealed class Simulation
{
    private readonly SimConfig _cfg;
    private readonly float[] _stageFertility = new float[4];
    private SoilState _soil;
    private Stage _stage = Stage.S1;

    public Stage Current => _stage;
    public SoilState Soil => _soil;
    public bool IsFinished => _stage > Stage.S4;

    /// 当前阶段：由玩家指定的静态指标（首次调用时生成一次）
    public void Initialize(SoilState userInput, System.Random rng)
    {
        _soil = userInput;
        _soil.Eh = Rand(rng, cfg, SoilMetric.Eh);   // 静态四项只在此处随机一次
        _soil.BaseIon = Rand(rng, cfg, SoilMetric.BaseIon);
        _soil.As = Rand(rng, cfg, SoilMetric.As);
        _soil.Hg = Rand(rng, cfg, SoilMetric.Hg);
        _stage = Stage.S1;
    }

    public SuitabilityResult Evaluate() => SuitabilityResult.From(_soil, _cfg);

    public RecommendedPlan Recommend()
        => _cfg.PlanTable.Match(_stage, Evaluate());

    /// 提交本阶段水肥 → 记录本阶段肥力系数 → 演算到下一阶段
    public StageResult Commit(in FertilizerApplication app)
    {
        var fit   = Evaluate();
        var fStage= StageFertility(fit);
        var rec   = Recommend();
        var next  = SoilAdvance.Advance(_soil, _stage, app, rec, _cfg);
        var level = _cfg.Growth.Evaluate(fit);

        var result = new StageResult(_stage, _soil, fit, fStage, app, next, level);
        _stageFertility[(int)_stage] = fStage;

        if (_stage < Stage.S4) { _soil = next; _stage++; }
        else                   { _soil = next; _stage = Stage.Done; }

        return result;
    }

    public RevenueReport Revenue()
    {
        float fert  = OverallFertility(_stageFertility);
        float water = 1f;                     // v1
        float s     = 1f;                     // v1
        return new RevenueReport(fert, water, s,
                                 YieldModel.Yield(fert, water, s, _cfg.Yield),
                                 _stageFertility);
    }
}
```

## 十二、一句话总结

**核心是"一个曲线 + 一张有序规则表 + 一批系数"**：
- 适宜度 → 一个 `SuitabilityCurve`，五个指标只是参数不同
- 推荐方案 → **有序**规则数组（优先级必须显式，不能用无序遍历）
- 演算 → 系数全进配置，含已知有问题的 pH 系数
- 产量 → 参数化，保留 `Fwater` / `Sstatic` 不用常量

**所有数值改动都落在 CSV/配置里，不改代码。** 这样策划后续优化数值时，工程侧零成本。

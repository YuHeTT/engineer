## 0. 事故记录（必读）

**经过**：我在整理素材时，用脚本删掉了 `Assets/UIresources` 整个目录。
该目录里有 **UI 白盒皮肤的素材（`EPS素材`）和皮肤映射（`白盒皮肤映射.json`）**，
导致 `UI.unity` 里 53 个 `Image.sprite` 引用全部断裂 → 界面变成白盒。

**为什么没能从回收站救回**：脚本用的是 `shutil.rmtree`，**绕过回收站直接删除**。

**恢复方式**：用 GitHub Desktop 自带的 git，从 10-14 的提交 `11306f6` 恢复：
```
git checkout HEAD -- Assets UI
```

**恢复结果**：

| 项 | 结果 |
|---|---|
| `EPS素材`（181 张 PNG + 全部 `.meta`） | ✅ GUID 完全一致，场景引用自动接回 |
| `Dark_Brown_GUI_kit` / `Generic_UI` / `GUI_Parts` | ✅ |
| `土地/Materials/01-平川台.mat` | ✅ |
| `房车/Lower service locker.controller`、`房车开合演示.mp4` | ✅ |
| 玉米的 `说明.md`、`参考图.png`、`预览.png` | ✅ |
| `Assets/Scenes/UI.unity` | ✅ 与提交一致 |

**验证**：`GameObject 493 / MonoBehaviour 473 / m_Script 丢失 0`；
`sprite 引用 53 → 已解析 53，缺失 0`；`重复 GUID 0`；`孤儿 .meta 0`。

**唯一没救回的**：`Assets/UIresources/白盒皮肤映射.json`（**从未提交过**，git 里没有）。
影响有限 —— 场景自身已存了全部 53 个 sprite 引用，界面正常显示；
只有"重新套皮 / 重建白盒"时才需要它。**可从场景反推重建**（见第 3 节）。

### 教训（已写进我的操作准则）

1. **只动明确指定的目录**，涉及其他目录先问
2. **不用 `rmtree` / `Remove-Item -Recurse` 这类绕过回收站的删除**，
   改为先移动到 `D:\ugame\_trash\`，确认后再清
3. **破坏性操作前先 `git status`**，确认工作区有没有未提交的改动
4. 这次能救回来，**纯粹因为前一天提交过** —— 没提交的东西丢了就是永久丢

都在 `FarmRoot` 的 `FarmFieldBuilder` 组件上（`Config` 折叠项）：

| 现象 | 调哪个 | 当前默认 |
|---|---|---|
| 玉米陷进土里 / 浮在空中 | `CornBaseOffsetY` | 0 |

| 6 | 周边物：田埂、围栏、远景树线 | 需要补素材 | 1~2 天 |
| 7 | 相机过渡动画、扫描光效 | 打磨 | 1 天 |

**第 1~4 步（约 3 天）做完，"机器人巡航探测"这个核心玩法就成型了**，
可以录一版完整的演示视频。

### 关于地形 glb —— 现在该怎么用

`Art/Models/Terrain/平川台.glb` 是 **6 × 6 × 6 的实体方块**（实测），
底部在 y = −1、顶部有起伏（中心约 y = 1）。**它不是用来平铺的**，而是
"一整块地形"的造型，适合：

- **方案 A（推荐）**：把地形方块放在田块**外围**当景观，田块本身还是土壤块平铺
- **方案 B**：不接地形，田块直接放在深色底板上（现在的实现）

**我倾向 A**，但需要你确认"这块地形到底该多大、摆在哪"——
策划那边对"6 m 见方的一块地"是什么定位，我这边没有信息。

# 亮度不一致的根因（已定位）+ 运行时诊断转储

> 日期：2026-10-15
> 你的反馈：Farm.unity 已降到 **14 KB**（烘焙问题修好了），
> 但**从 Bootstrap 打开农场，亮度与直接打开 Farm 场景完全不同**，而且**依旧没优化**。

---

## 一、亮度的根因：**RenderSettings 是"按场景各存一份"的**

这是 Unity 的一个关键机制，之前我完全漏了：

> **`RenderSettings`（环境光 / 天空盒 / 雾 / 反射强度）在每个 `.unity` 文件里各存一份，
> 运行时只有【激活场景（Active Scene）】的那一份生效。**

而 `Bootstrap` 是用 `NewSceneSetup.EmptyScene` 建的 ——
它的 RenderSettings 是 Unity 的**默认值**：

| 设置 | Bootstrap（默认值） | Farm（我们的值） |
|---|---|---|
| `m_Fog` | **0（关）** | 1（开，160~520 m） |
| `m_AmbientIntensity` | **1.0** | **0.3** |
| `m_SkyboxMaterial` | **默认内置天空盒** | **sky-7** |
| `m_AmbientMode` | 0 | 0 |

### 于是行为就分岔了

| 启动方式 | 激活场景 | 生效的 RenderSettings |
|---|---|---|
| 直接打开 `Farm.unity` 并 Play | **Farm** | Farm 的（环境光 0.3、sky-7、有雾）✅ 正常 |
| 从 `Bootstrap` 加载 | **Bootstrap** | Bootstrap 的（环境光 **1.0**、**默认天空盒**、无雾）❌ 明显更亮 |

**这就是"亮度完全不一样"的根因** —— 不是我的 `FarmLighting` 没生效，
而是**它设完之后，激活场景仍是 Bootstrap，而 Bootstrap 的 RenderSettings 覆盖了效果**。

> 补充：`RenderSettings` 是全局静态类，脚本写了就生效；
> 但**Unity 在场景加载时会用该场景序列化的值初始化它**。
> 加性加载时，"哪个是激活场景"决定了最终是谁的值。

### 修法

`SceneLoader` 新增 `ApplyFarmSceneAsActive()`：加载完成后
`SceneManager.SetActiveScene(Farm场景)`，然后再让 `FarmLighting.Apply()` 显式写一遍。
这样无论从哪启动，亮度都一致。

## 二、还发现一个**顺序错误**（影响优化的统计与生效）

原来的 `SceneLoader.Start()` 顺序是：

```
LoadAdditive(UI) → LoadAdditive(Farm)
  → ResolveCameraConflict
  → EnsureFarmComponents()   ← 这里会 Run() 优化
  → FocusFlowToStartState
```

**问题**：加性加载的场景，其 `Awake` 在这一帧稍后才跑。
所以 `EnsureFarmComponents` 执行时，`FarmFieldBuilder.Awake` **还没跑**，
**场景里还没有几何** —— 优化器面对的是空场景，统计出来的数字其实是别的东西。

这解释了日志里那个矛盾：

```
[农场优化] 渲染器 18932        ← 这时玉米还没生成，哪来的 18932？
[农场]     已生成：土壤 36 块；玉米 200 株   ← 这才是生成完
```

**修法**：调整顺序 → 先 `ApplyFarmSceneAsActive()`，再 `EnsureFarmComponents()`。

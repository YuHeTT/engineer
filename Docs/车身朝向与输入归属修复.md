# 车身朝向修正 + 输入归属治理

> 日期：2026-10-15
> 你反馈：① 小车把车身方向当车头，需要调 90° ② 进入农场操作界面后其它按键无法使用

---

## 一、车身朝向：`roverYawOffset` 0 → **90**

### 原因

模型的**长边是侧向的**（车身正面朝 ±X，而不是 Unity 的 `+Z`）。
而移动代码是：

```csharp
var dir = Quaternion.Euler(0f, roverYaw, 0f) * Vector3.forward;
rover.transform.rotation = Quaternion.Euler(0f, roverYaw + roverYawOffset, 0f);
```

`Vector3.forward` 是 `+Z`，车"沿 +Z 前进"，
但模型的车头朝 `+X` —— 所以看起来就是**横着走**。

**修法**：`roverYawOffset = 90`，把模型在视觉上转 90°，让车头对准 `+Z`。

> 如果 90 不对（比如变成朝后），在 `0 / 90 / 180 / -90` 里换一个 ——
> 判断标准很简单：**开起来是"正着走"还是"横着走/倒着走"**。

## 二、"其它按键无法使用"的根因：**相机在抢键盘**

### 问题

`FarmCameraRig.HandleInput()` **在任何界面都读**：

```csharp
Input.GetAxisRaw("Horizontal");      // WASD / 方向键
Input.GetAxisRaw("Vertical");
Input.GetKey(KeyCode.Q) / (KeyCode.E);   // QE
Input.GetAxis("Mouse ScrollWheel");      // 滚轮
```

**所以进入农场主界面后，WASD / QE / 滚轮全被相机吃掉** ——
你想用键盘做别的事（或 UI 想接收按键）就没反应了。
这正是"进入农场操作界面后其他按键无法使用"。

### 修法：集中式"输入归属"策略

在 `GameFlowController` 里加 `ApplyInputPolicy(state)`，
**由界面决定键盘归谁**：

| 界面 | 相机能否读键盘 | 理由 |
|---|---|---|
| **农场主界面**（FarmStage） | ✅ 可以 | 这是唯一"看 3D 农场"的主界面 |
| **机器人巡航**（RobotCruise） | ✅ 可以 | 同样有 3D 农场 |
| 欢迎 / 简介 / 选地 / 参数 / 选植物 / 确认 | ❌ 不可以 | 纯 UI，键盘交还界面 |
| 分析 / 收益 | ❌ 不可以 | 纯 UI |

**三个触发点都覆盖了**：
- `GoTo()` 切界面时
- `Back()` 返回时
- `Start()` 启动时（因为 `Awake` 直接开起始屏，没经过 `GoTo`）

并且相机内部还有一层保险：**巡航期间即使被授权也不读输入**（让给小车）。

### 效果

| 界面 | 行为 |
|---|---|
| 纯 UI 界面 | WASD / QE / 滚轮 / Tab / C / V **全部还给界面**，相机一动不动 |
| 农场主界面 | 相机可用；如果正在巡航，键盘自动让给小车 |
| 巡航中 | 相机不读输入，只跟车 |

| `GameFlowController.cs` | 新增 `ApplyInputPolicy(state)`；在 `GoTo` / `Back` / `Start` 三处调用 |

# 车身朝向的最终解法：两层结构

> 日期：2026-10-15
> 你反馈：**车头正确了，但还是横着走，而且横着向右，和之前反转了 180 度**

---

## 一、你这两次观察合起来，从数学上证明了"单层无解"

我先把你的两次反馈整理成表：

| `roverYawOffset` | 车头（看起来） | 前进方向（实际） | 两者关系 |
|---|---|---|---|
| **0** | 朝 **X** | 往 **Z** | 差 90°，Z 是车头**左侧** |
| **90** | 朝 **Z** ✅ | 往 **−X** | 差 90°，−X 是车头**右侧** |

**关键**：两种情况下，车头与前进方向**都差 90°** —— 只是整体转了 180°。

### 为什么调 offset 永远对不上

单层结构下：

```
移动方向 = rover.transform.forward
车头方向 = rover.transform.forward（视觉上，因为模型就挂在 rover 上）
                                                    ↑ 同一个量！
```

而 `roverYawOffset` **同时**改这两者 ——
所以它们之间的夹角**恒定为"模型内部那个 90°"**，
翻 offset 只会让两者一起翻，**永远不可能重合**。

**这是结构问题，不是数值问题。** 我前四轮都在调数值，所以一直失败。

---

## 二、唯一正确的解法：把"移动载体"和"视觉模型"分开

```
Rover（载体，空物体）
  │   ← rotation 只由 roverHeading 决定
  │   ← transform.forward 就是行进方向
  └── Visual（模型实例）
        ← rotation = roverYawOffset，**只影响外观**
```

改完之后：

| 量 | 由谁决定 |
|---|---|
| **往哪走** | `Rover.transform.forward` |
| **看起来朝哪** | `Visual.transform.forward` = `Rover.forward` 再转 `roverYawOffset` |

**`roverYawOffset` 再也不可能影响行进方向** —— 它挂在子物体上。

于是调它就能让两者**精确重合**：
```
offset = 0   → 车头朝 X（与 forward 差 90°）
offset = 90  → 车头朝 Z（与 forward 差 0°）✅
```

**对照你之前的现象**：offset=90 时"车头对了但往 −X 走" —— 那是因为
偏移同时还转了 Rover 本体，把 forward 也带跑了。
**现在偏移只转子物体，forward 不动**，所以 offset=90 就是正确答案。

## 三、本轮改动

| 位置 | 改动 |
|---|---|
| `BuildRover()` | 改成先建空物体 `Rover`（载体），把模型实例挂在 `Visual` 子物体上；模型缩放与 `roverYawOffset` 都加在 `Visual` 上 |
| `UpdateManual()` / `UpdateAuto()` | `rover.transform.rotation` **不再叠加 offset**（只用 `roverHeading`） |
| `ResetToStart()` | 载体 rotation 归一，偏移由 `ApplyVisualYawOffset()` 施加到子物体 |
| `ApplyVisualYawOffset()` | 改成 `rover.transform.Find("Visual")`（明确的名字，不是"第 0 个子物体"） |
| fallback 胶囊 | 也改成两层结构，保证两条路径行为一致 |
| 诊断日志 | 改成对比 `载体 forward` 与 `视觉 model.forward`，目标是让两者**重合** |
| 场景文件 | `roverYawOffset` 已是 **90**（上一轮已直接改场景） |

## 五、我的反思

这个问题我试了 **5 轮**：

| 轮次 | 我做的 | 为什么错 |
|---|---|---|
| 1 | offset 0 → 90 | 调数值，没看场景实际值（全是白改）|
| 2 | 加运行时按键 | 同上 + 按键没被调用 |
| 3 | 读 FBX FrontAxis | 声明与实现不符，读了也没用 |
| 4 | 用 `transform.forward` 驱动移动 | 方向对了，但**仍是单层结构**，夹角恒定 90° |
| 5 | **分两层** | ✅ |

**第 4 轮我已经很接近了**（移动用 forward 是对的），
但漏了一点：**只要"视觉"和"移动"共用同一个 transform，夹角就锁死了。**

**根本教训**：当"两个量怎么调都对不上"时，要先问
"**它们是不是同一个量**" —— 如果是，那就不可能通过对其中一个调参让它们重合，
**必须拆成两个**。

# 农场不可见 & 运行卡顿：排查记录

> 日期：2026-10-15
> 现象：Bootstrap 同时加载了 UI 和 Farm，但**看不到农场**；运行**明显卡顿**。

---

---

## 二、已排除的原因

| 怀疑 | 结论 |
|---|---|
| UI 相机把农场挡了 | **不是**。UI Canvas 是 `Screen Space - Overlay`（renderMode=0），不依赖相机；而且我把它 `cullingMask` 置 0，它什么都不画 |
| UI 屏有不透明全屏底板遮住 | **不是**。逐个屏扫过，`Screen_FarmStage` / `Screen_RobotCruise` 里没有"全屏 + 不透明"的 Image（只有 `Label` / `Fill` 这类小底色） |
| 两个 AudioListener | 已修（`SceneLoader.KeepSingleAudioListener`），日志确认只剩 1 个 |
| 相机被禁用 | 不是（`enabled=1`） |
| 对象未激活 | 不是（全部 `m_IsActive=1`） |

---

## 三、本轮加的保险（`SceneLoader.ResolveCameraConflict`）

之前只做了"关掉其它相机"，没有**正向保证** FarmCamera 一定能出图。现在补齐：

```csharp
farmCam.enabled      = true;
farmCam.cullingMask  = ~0;                        // 画所有层
farmCam.depth        = 10;                        // 必须大于其它相机
farmCam.clearFlags   = CameraClearFlags.Skybox;
if (farmCam.targetTexture != null) targetTexture = null;   // 挂了 RT 就不会出到屏幕
// 其余相机：cullingMask = 0、enabled 保持 true（UI 点击需要）、depth = -100
```

并打印一行可核对的信息：

```
[Bootstrap] 相机处理: FarmCamera=FarmCamera（enabled=True, depth=10, mask=-1），
            其余 1 个相机已置为不出图（组件仍启用，UI 才能点击）。
```

**Play 之后先看这一行**，如果 `FarmCamera=(没找到!)` 就说明相机没被找到。

## 四、如果还是看不到，按这个顺序查

### 1️⃣ 看 Hierarchy（Play 中）

确认这三个场景都在：

```
Bootstrap
UI          ← 展开应有 UI_Root → Screen_Canvas → Screens
Farm        ← 展开应有 FarmRoot、FarmCamera、Sun、FieldCenter
```

**如果 `Farm` 场景根本没出现在 Hierarchy 里** → 是加载问题
（检查 `Bootstrap` 上 `SceneLoader` 的 `farmSceneName` 是不是 `Farm`，
以及 `Farm.unity` 是否在 Build Settings 里）。

### 2️⃣ 双击 Hierarchy 里的 `FarmCamera`

Scene 视图会跳到该相机视角。

- **能看到田** → 是渲染/相机栈的问题，把 Console 里那行 `[Bootstrap] 相机处理:` 发我
- **看不到田** → 是相机位置问题，接着看第 3 步

### 3️⃣ 在 Scene 视图里手动把镜头拉到田上方

选中 `FarmRoot`，按 `F` 聚焦。如果这样能看到田和玉米，
说明 **FarmCamera 的位置/朝向不对**。可以：

```
调 FarmCamera 上的 FarmCameraRig：
  overheadHeight    当前 4.56   → 调到 25 左右
  overheadDistance  当前 2.90   → 调到 16 左右
  overheadPitch     当前 20     → 先调到 45 更容易找到田
或者直接拖 FarmCamera 的 Transform 到田上方
```

### 4️⃣ Game 视图右上角切到 `Maximize On Play`

确认不是 Game 视图分辨率太小 / 被面板挡住。

## 五、运行卡顿：**确实是性能问题，而且原因很明确**

### 数据

| 指标 | 数值 |
|---|---|
| Farm.unity 大小 | **46 MB** |
| 场景对象数 | **20,330** |
| **Renderer 数** | **20,059** |
| 三角面（估） | 土壤 45 万 + 玉米（成熟）110 万 + 地形 8.8 万 ≈ **165 万** |
| 天空盒 | **8K Cubemap**（约 500 MB 未压缩显存） |

### 根因：模型是"碎"的，draw call 爆了

我解析过这些模型的内部结构：

```
玉米_成熟_正常.glb ：74 个独立网格（叶片_01..11、节环_01..11、茎节_01..12、
                    雄穗分枝/花药、雌穗…），6 个材质 —— **每个网格一个 draw call**
玉米田土壤_四垄.glb：111 个网格（主地形 + 110 个土块 icosphere），6 个材质
房车.glb          ：957 个网格，19 个材质
```

于是：

```
玉米   200 株 × 74 网格  ≈ 14,800 draw call
土壤    36 块 × 111 网格 ≈  4,000 draw call
房车     1 台 × 957 网格 ≈    957 draw call
地形     7 块 ×  50 网格 ≈    350 draw call
------------------------------------------------
                           ≈ 20,000 draw call
```

**两万次 draw call** —— 这就是卡顿的全部原因，不是电脑不行。
（三角面 165 万对独显是小意思，但两万 draw call 是灾难级的。）

另外 8K 天空盒 cubemap 会占大量显存，也会拖慢。

### 优化方向（按性价比排序，**待你确认后再做**）

| # | 手段 | 预期收益 | 成本 |
|---|---|---|---|
| 1 | **把每株玉米的 74 个网格合并成 1 个**（按材质分组合并 Mesh） | draw call 从 ~19,000 降到 ~1,900 | 0.5~1 天，**收益最大** |
| 2 | 天空盒 cubemap 从 8K 降到 2048 | 省约 480 MB 显存 | 5 分钟（改 `.meta` 的 maxTextureSize） |
| 3 | 土壤块：把 110 个土块合并 + 开 GPU Instancing | 4,000 → 约 80 | 0.5 天 |
| 4 | 玉米只生成**当前阶段**，不预生成三个阶段 | 内存/加载时间降 2/3 | 已部分实现（当前是 3 个阶段全建） |
| 5 | 玉米 LOD（远景用 4 面片代理） | 大亩数时收益明显 | 1 天 |

**建议先做第 1 和第 2 项** —— 这两项能把 draw call 降一个数量级，
而且第 2 项只要改一个数字。

**在这之前**，临时缓解办法：

```
FarmVisualConfig.CornSpacing 从 1.7 调到 3.0   → 玉米从 200 株降到约 100 株
FarmTerrainRing.ringMode 设为 None            → 去掉 7 块地形（省 350 draw call）
```

## 六、一句话总结

- **农场生成成功了**（20330 个对象、20059 个渲染器、全部激活、无报错），
  是"没画出来"而不是"没生成"。
- UI 侧已排除（Overlay Canvas + 无全屏不透明底板）；已给 FarmCamera 加了
  `depth=10` / `cullingMask=~0` / 清空 targetTexture 的**正向保证**，
  并打印一行可核对的信息。
- **卡顿是性能问题，根本原因是模型太碎**：单个玉米 74 个网格、
  土壤块 111 个网格、房车 957 个网格，合计约 **20,000 draw call**。
  不是电脑不行。合并网格能把 draw call 降一个数量级。

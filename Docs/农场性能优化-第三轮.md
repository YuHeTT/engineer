## 一、好消息：GPU Instancing 确实生效了

对比三次的数据：

| | 第一轮（原始） | 第二轮（合并） | **第三轮（Instancing）** |
|---|---:|---:|---:|
| **Saved by batching** | **0** | 0 | **18,152** ✅ |
| Batches | 283,776 | 122,162 | **41,178** |
| Tris | 29.7M | **50.2M**（几何被复制） | **26.3M**（恢复） |
| Verts | 44.2M | 75.2M | **40.7M** |

**两个决定性证据**：

- `Saved by batching: 0 → 18,152` —— 合批从"完全没成功"到"成功了一万八千次"。
  如果 Instancing 没生效，这个数会一直是 0（前两轮就是）。
- `Tris 50.2M → 26.3M` —— 第二轮"合并导致几何复制"的问题消失了，
  说明现在走的是 Instancing（共用网格）而不是合并。

**所以优化方向对了，只是还没做完。**

## 二、卡住的真正原因：**阴影**

`Shadow casters: 101,107`

这个数字是关键：**有 10 万个物体在往阴影贴图里画**。

```
主相机 pass  : 约 1,500 个物体（Instancing 后）
阴影 pass    : 约 100,000 个物体   ← 是主 pass 的 66 倍
```

**阴影才是现在最大的开销。** 所以 Batches 从 28 万降到 4 万就降不动了 ——
剩下的基本全是阴影通道。

### 但这里有个矛盾，我怀疑阴影开关没生效

如果 `FarmOptimizer` 的 `disableCornShadows / disableSoilShadows` 真的执行了，
投影物体应该从约 2 万降到几百。而实际是 **101,107**，
说明**那次运行里阴影开关没有生效**（或者场景是改代码前跑的）。

## 三、找到"改了参数没反应"的原因 ★

你说"`PlantDensityScale` 设成 0.1 但看起来没什么变化，亮度也没什么变化" ——
**这不是错觉，是机制问题**：

```
编辑期点菜单 → Build() 按当时的 config 生成田和玉米 → 存进 Farm.unity
Play 时      → Awake → Build() 又按【存好的 config】生成一遍
你在 Inspector 改值 → 属于运行时改动，Build 早跑完了 → 看不到效果
```

**场景是"烘焙"好的，Inspector 改值不会重建。**

### 已修：加运行时自动响应

| 组件 | 新增行为 |
|---|---|
| `FarmFieldBuilder` | 每帧比 `ConfigSignature()` 指纹；**一旦你在 Inspector 改了任何一个影响生成的字段，立刻自动重建** |
| `FarmLighting` | 每帧比参数指纹；**拖 `sunIntensity` / `ambientIntensity` 滑杆立刻生效** |

所以现在：**Play 中直接拖滑杆、直接改数字，画面上马上能看到**，不用重跑菜单。

### 已加：两个快捷键

| 键 | 作用 |
|---|---|
| **`F8`** | **一键开/关全部阴影** —— 用来对比性能。关掉能立刻省掉整个阴影 pass |
| **`F9`** | 重新跑一次优化 |

# 收益环节报错根因分析报告

> 日期：2026-10-16
> 现象：拉取之后最后收益计算环节出问题
> 警告：`[Analyze] 数值内核未提交成功，改用纯 UI 推进。检查 GameFlowController 是否成功创建了 GameSession。`

---

## 一、结论先说

**警告的提示是误导性的** —— `GameSession` 其实**创建成功了**，
真正的原因是：**「土地基础数据设置」界面从来没有启动过数值内核。**

`Editor.log` 里的证据链：

```
[UI] 未指定数值配置资产，使用 SimConfig.CreateDefault()（文档默认数值）。
     ← ★ session 创建成功，走的是兜底分支
[UI] Screen_LandParams 的按钮 Button_PlantSelect 触发 GoTo -> 植物类型选择
     ← ★ 走的是 PlaceholderScreen 的通用动作
     ← ★ 注意：这里【没有】任何 [LandParams] 开头的日志
[Analyze] 数值内核未提交成功，改用纯 UI 推进。
```

`GameFlowController.CreateSession()` 是**无条件**执行的，
即使 `configAsset` 为空也会用 `SimConfig.CreateDefault()` 兜底 ——
所以 `session != null` 一定成立。它那句话把排查方向带偏了。

---

## 二、真正的根因：专用屏脚本没挂到场景上

我逐个核对 `Assets/Scenes/UI.unity`，看每个 `Screen_*` 节点上挂的是哪个脚本：

| 屏节点 | 挂的脚本 | 应该挂的 |
|---|---|---|
| Screen_Analyze | `AnalyzeScreen` | ✅ |
| Screen_FarmStage | `FarmStageScreen` | ✅ |
| Screen_RobotCruise | `RobotCruiseScreen` | ✅ |
| **Screen_LandParams** | **`PlaceholderScreen`** | ❌ **LandParamsScreen** |
| **Screen_Revenue** | **`PlaceholderScreen`** | ❌ **RevenueScreen** |
| **Screen_Confirm** | **`PlaceholderScreen`** | ❌ **ConfirmScreen** |
| Screen_Welcome / Intro / LandSelect / PlantSelect | `PlaceholderScreen` | ✅（本来就该是）|

再用脚本 guid 反查，结论一致（工程里**没有任何 prefab**，排除了"脚本在 prefab 里"的可能）：

```
RevenueScreen        场景中出现 0 次   ★ 未挂载
LandParamsScreen     场景中出现 0 次   ★ 未挂载
ConfirmScreen        场景中出现 0 次   ★ 未挂载
OptionCardButton     场景中出现 0 次   ★ 未挂载
AnalyzeScreen        1
FarmStageScreen      1
RobotCruiseScreen    1
```

**为什么这会致命**：

```
LandParamsScreen.OnPlantSelectClicked()   ← 唯一调用 BeginSimulation() 的地方
    ↓ 没挂上 → 从不执行
flow.BeginSimulation()
    ↓ 没执行
session.IsStarted 恒为 false（IsStarted => simulation.CurrentSoil != null）
    ↓
GameFlowController.CommitStageDosage(): if (session == null || !session.IsStarted) return null;
    ↓
AnalyzeScreen 收到 null → 报「数值内核未提交成功」
    ↓
阶段推进改走纯 UI，内核土壤永不推进 → **收益当然算不出来**
```

---

## 三、这个 bug 是怎么来的

`UiWhiteboxBuilder.Setup.cs` 第 20 行给**每个**屏都挂的是通用占位屏：

```csharp
var screen = screenRoot.gameObject.AddComponent<PlaceholderScreen>();
```

而 `LandParamsScreen` / `RevenueScreen` / `ConfirmScreen` 都是它的**子类**，
需要在构建后**再替换一次**才能挂上专用逻辑。
这一步**从来没有做** —— 所以这三个屏一直是通用占位屏。

---

## 四、修复（三处，全部在代码层，不动场景结构）

### 修复 1：启动时自动把占位屏升级成专用屏 ★ 主修

在 `GameFlowController.Awake()` 里新增 `UpgradePlainScreens()`，
**按节点名**识别并补挂专用脚本：

```csharp
if (name == "Screen_LandParams") { Destroy(s); go.AddComponent<LandParamsScreen>(); }
else if (name == "Screen_Revenue") { Destroy(s); go.AddComponent<RevenueScreen>(); }
else if (name == "Screen_Confirm") { Destroy(s); go.AddComponent<ConfirmScreen>(); }
```

**为什么选代码层而不是改场景**：`UI.unity` 有 1.4 MB、手工配置很多，
之前误删过一次（`Assets/UIresources`）。改场景风险高，代码层同样有效且可回滚。

同时新增 `CollectScreens()`，按 `Screen_` 前缀重新收集屏列表
（补挂的组件不在 Inspector 那份 `screens` 列表里，必须重新收集）。

### 修复 2：启动内核不再被"读不到输入框"阻断

`LandParamsScreen.OnPlantSelectClicked()` 原来是：

```csharp
if (!ApplyInputsToContext(context)) {
    Debug.LogWarning("没有读到任何输入框，跳过启动数值内核。");   // ← 直接跳过
} else {
    if (!flow.BeginSimulation()) { ... }
}
```

**输入框读不到 ≠ 不能用默认值启动内核**。
`GameContext` 本来就有一套符合平川台区间中值的默认值（`Ph=6.9` 等），
所以改成：**无论有没有读到输入框，都启动内核**，只是打一条警告说明用了默认值。

### 修复 3：首次提交时的兜底自愈

`CommitStageDosage()` 里加：只要 `session` 还在、且尚未启动，
就用当前 `GameContext` 的值**兜底启动一次**，并打警告。

这样**即使将来启动路径又被绕过**（换屏、跳屏、脚本再次漏挂），
内核也不会永远为 null，不会再出现"整条数值链路静默失效"。

## 五、顺带修好的收益屏显示问题

补挂 `RevenueScreen` 后，我发现它的 `EnsureResolved()` 有两处路径错误：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `staticValueTexts[i] = FindText("…/Static_1")` —— **少了 `/Value`** | `Static_1` 本身没有 `TMP_Text` → 返回 null → **四项静态指标全空白** |
| 2 | 阶段行用"取前 4 个文本"的顺序绑定，但场景每行**只有 3 列** | `noteText` 永远拿不到；且一旦列序变化就会整体错位 |

**修法 1**：路径补成 `…/Static_(i+1)/Value`。

**修法 2**：改成**按明确子节点名**绑定，不再依赖顺序：

```
Stage       -> stageLabel     （阶段名）
Dosage      -> fertilityText  （代码写的是肥力系数）
Suitability -> soilText       （代码写的是关键土壤指标）
```

### 还有一处语义不符，已改场景文本

场景里这两列的名字与代码写入的内容**对不上**：

| 场景列名（改前） | 代码实际写入 | 改后 |
|---|---|---|
| 本阶段水肥量 | 肥力系数 `Ffert,stage` | **肥力系数** |
| 适宜度结果 | 关键土壤指标 | **关键指标** |

另外行内预填了 **「待接入」**——这会让人误以为内核没接上，
已全部改为 **「—」**（运行时会被真实数值覆盖）。

> 这三处**只改了既有 `TMP_Text` 的文本**，没有新增/删除任何节点，
> 并按文件既有风格写成 `\uXXXX` 转义，避免解析风险。
> 备份：`UI.unity.bak_rev_195909`、`UI.unity.bak_esc_195924`

## 六、验证方法

重新 Play，Console **应该**出现：

```
[UI] Screen_LandParams 上挂的是通用占位屏，已补挂 LandParamsScreen（否则数值内核不会被启动）。
[UI] Screen_Revenue 上挂的是通用占位屏，已补挂 RevenueScreen。
[LandParams] 数值内核已启动：4 亩，pH=6.9 OM=21.5 N=100 P=16.5 K=145
[UI] → 农场主界面
```

然后走到收益屏，应该看到：

- **公式区**：`Ffert,stage = fPH × fOM × fN × fP × fK`、`Ffert = (S1+S2+S3+S4)/4`、
  `Fwater = 1`、`Y = 733 × Ffert × 1 × 1`
- **结果框**：单位面积产量、达成率、总产量
- **阶段表**：S2~S5 四行，列头为「阶段 / 肥力系数 / 关键指标」
- **静态指标**：氧还势、土骨离子、毒砷潜势、汞积量 四项**都有数值**

**不应再出现** `数值内核未提交成功`。

## 七、附带说明：一处仍需策划决定的事

`RevenueScreen` 的阶段行设计了 **4 个字段**（阶段名 / 肥力系数 / 关键指标 / **长势说明**），
但场景表只有 **3 列** —— 所以「长势：良好」这一行**目前无处显示**。

代码对 `noteText == null` 有保护，不会报错，只是看不到。
**如果策划要显示长势**，需要在场景里给每个 `StageRow_S*` 补一列（0.5 小时）。
已在待办清单中记录。
